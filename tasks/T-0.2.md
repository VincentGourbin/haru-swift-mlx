## Étapes
1. **Accord de Vincent requis** (exécute du code amont) : `python3 -m venv .venv-ref && .venv-ref/bin/pip install -e reference/haru/haru_mlx`.
2. `pgrep -fl "mlx|python|ollama|qwen38"` : aucune autre charge GPU ; secteur, profil haute performance.
3. Pour `Q` dans {aucun, 8} et `C` dans {live, burst}, dans l'ordre A/B/B/A (live bf16, live 8, live 8, live bf16, puis burst) :
   `.venv-ref/bin/python -I Scripts/reference/baseline.py --model "$HARU_MODELS_DIR/higurashi-ai/Haru-4B" [--quantize 8] --cadence C --seconds 60 --out .local-runs/bench.noindex/baseline-<Q>-<C>-<n>.json`
4. Puis, en 8 bits seulement : `--cadence live --warm-ms 30` et `--cadence live --warm-ms 30 --feed` (chemin comparable au futur chemin Swift).
5. Recopier p50/p95/p99/max, `late_frames`, pics mémoire dans le fichier de benchmark ; noter la
   version MLX, la révision amont `7fe6b76`, l'heure.

## Validation (dans l'ordre, arrêt au premier échec)
1. Les 8 fichiers JSON existent et `frames` ≥ 400 dans chacun.
2. L'écart live entre les deux passes d'une même précision est ≤ 5 % sur p50 (sinon refaire après refroidissement).
